Validation
 Validation means checking that the data sent to your API is actually correct 
 before you use it or save it.

Why it matters — what happens without it
js
app.post('/notes', (req, res) => {
  const note = {
    id: nextId++,
    title: req.body.title,      // what if this is missing?
    content: req.body.content
  };
  notes.push(note);
  res.status(201).json(note);
});

If someone sends this:

json
{ "content": "oops no title" }

You'd end up saving a note with title: undefined — silently broken data, no error, no
 warning. Multiply that across a real app and your database fills with garbage.

Basic Manual Validation (the beginner way)
js
app.post('/notes', (req, res) => {
  const { title, content } = req.body;

  if (!title || typeof title !== 'string') {
    return res.status(400).json({ error: "Title is required and must be a string" });
  }
  if (!content || typeof content !== 'string') {
    return res.status(400).json({ error: "Content is required and must be a string" });
  }

  const note = { id: nextId++, title, content };
  notes.push(note);
  res.status(201).json(note);
});

Notice: this ties directly back to what we covered — 400 Bad Request is the correct 
status code when the client sends bad data.

The Better Way — Validation Libraries

Once your API grows, manual if checks get messy fast. Most real Node.js projects use
 a library. The most popular for beginners:

zod (modern, very popular, great error messages):

js
import { z } from 'zod';

const noteSchema = z.object({
  title: z.string().min(1),
  content: z.string().min(1)
});

app.post('/notes', (req, res) => {
  const result = noteSchema.safeParse(req.body);
  
  if (!result.success) {
    return res.status(400).json({ error: result.error.issues });
  }

  const note = { id: nextId++, ...result.data };
  notes.push(note);
  res.status(201).json(note);
});

This does in a few lines what would take many manual if statements, and gives you clean,
 structured error messages for free.

Validation Rules of Thumb
Check	Example
Required fields present?	title must exist
Correct type?	title must be a string, not a number
Correct format?	An email field should look like an email
Reasonable length/range?	title shouldn't be 10,000 characters
PATCH vs POST validation differs	POST needs all required fields; PATCH only validates 
the fields actually sent
